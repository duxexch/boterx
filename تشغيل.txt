===========================
شرح تشغيل بوت DUX محليًّا وعلى VPS
===========================

هذا الملف يشرح تشغيل سكربت البوت:
    comprehensive_bot.py

بنفس الشكل الذي كان يعمل به على Replit، مع الاعتماد على ملف .env لتخزين الإعدادات الحساسة (التوكن و IDs الأدمن).

---------------------------------
1) المتطلبات العامة (محلي و VPS)
---------------------------------

- Python 3.9 أو أحدث
- اتصال إنترنت مستقر
- توكن بوت تيليجرام من BotFather
- Telegram ID للأدمن (يمكن الحصول عليه من بوت مثل: @userinfobot أو @RawDataBot)

ملفات المشروع الأساسية:
- comprehensive_bot.py
- ملفات CSV (users.csv, transactions.csv, companies.csv, payment_methods.csv, exchange_addresses.csv, complaints.csv, system_settings.csv ...)
  * لو غير موجودة، السكربت يقوم بإنشائها تلقائيًا في أول تشغيل.


===========================
2) التشغيل محليًّا (على جهازك)
===========================

يمكن أن يكون النظام Windows أو Linux أو macOS. الخطوات العامة متشابهة.

-----------------------
2.1 تجهيز المجلد
-----------------------

1) فك ضغط مشروع البوت (TaskFlowAIgggg-main.zip) في مجلد، مثلًا:
   - على ويندوز: C:\Users\اسمك\Desktop\TaskFlowAIgggg-main
   - على لينكس: /home/اسمك/TaskFlowAIgggg-main

2) تأكد أن الملف التالي موجود داخل المجلد:
   - comprehensive_bot.py

------------------------------
2.2 إنشاء بيئة عمل افتراضية (اختياري لكنه مفضّل)
------------------------------

من داخل المجلد:

- على Windows (PowerShell أو CMD):

    python -m venv venv
    venv\Scripts\activate

- على Linux / macOS:

    python3 -m venv venv
    source venv/bin/activate

------------------------------
2.3 تثبيت مكتبة python-dotenv
------------------------------

هذه المكتبة تستخدم لقراءة ملف .env بسهولة:

    pip install python-dotenv

(إن لم تكن مضافة سابقًا في المشروع.)

------------------------------
2.4 التأكد من تحميل .env داخل الكود
------------------------------

في أعلى ملف comprehensive_bot.py (مع الاستيرادات الأخرى)، يجب أن يكون موجودًا السطران التاليان:

    from dotenv import load_dotenv
    load_dotenv()

لو غير موجودين؛ أضفهما مرة واحدة بعد بقية الـ imports.

------------------------------
2.5 إعداد ملف .env
------------------------------

في نفس مجلد comprehensive_bot.py، أنشئ ملف باسم:

    .env

واكتب بداخله (مع استبدال القيم):

    BOT_TOKEN=ضع_توكن_البوت_من_BotFather_هنا
    ADMIN_USER_IDS=123456789,987654321

شرح المتغيرات:

- BOT_TOKEN:
    التوكن الذي يعطيه لك BotFather عند إنشاء البوت.

- ADMIN_USER_IDS:
    قائمة Telegram IDs للأدمن، مفصولة بفواصل.
    مثال:
    ADMIN_USER_IDS=123456789
    أو:
    ADMIN_USER_IDS=123456789,987654321

هؤلاء الأدمن هم الذين تصلهم الإشعارات الفورية (طلبات إيداع، سحب، شكاوى، تسجيل جديد، ...).

------------------------------
2.6 تشغيل البوت محليًّا
------------------------------

1) افتح Terminal أو CMD جديد.
2) انتقل إلى مجلد المشروع:

   - Windows:
        cd "C:\Users\اسمك\Desktop\TaskFlowAIgggg-main"

   - Linux:
        cd ~/TaskFlowAIgggg-main

3) فعّل البيئة الافتراضية إن كنت أنشأتها:

   - Windows:
        venv\Scripts\activate

   - Linux:
        source venv/bin/activate

4) شغّل البوت:

   - Windows:
        python comprehensive_bot.py

   - Linux:
        python3 comprehensive_bot.py

5) إذا سارت الأمور بشكل صحيح، سترى في السجل (الكونسول) سطرًا مثل:

        ✅ نظام DUX الشامل يعمل: @اسم_البوت

6) الآن جرّب من تيليجرام:
    - ابحث عن البوت باسم المستخدم (الذي أنشأته في BotFather)
    - أرسل /start
    - جرّب عمل طلب إيداع أو سحب أو شكوى من حساب عميل
    - تأكد أن حساب الأدمن (الموجود في ADMIN_USER_IDS) يستقبل إشعارًا فوريًا.

ملاحظة:
- لإيقاف البوت، اضغط Ctrl + C في نافذة التشغيل.


===========================
3) التشغيل على VPS (Ubuntu مثالًا)
===========================

هنا نفترض أن لديك سيرفر Ubuntu أو أي توزيعة لينكس مشابهة، وتستعمل مستخدم عادي (مثلاً: ubuntu أو root أو أي مستخدم آخر).

-----------------------
3.1 نسخ المشروع إلى VPS
-----------------------

يمكن ذلك بأكثر من طريقة، مثل:

- عبر SFTP (باستخدام FileZilla أو WinSCP)
- أو عبر scp (من جهازك المحلي):

    scp -r TaskFlowAIgggg-main youruser@yourserver_ip:/home/youruser/

بعد النسخ، على السيرفر:

    cd /home/youruser/TaskFlowAIgggg-main

------------------------------
3.2 تثبيت Python و venv (مرة واحدة)
------------------------------

على Ubuntu:

    sudo apt update
    sudo apt install -y python3 python3-venv python3-pip

------------------------------
3.3 إنشاء بيئة افتراضية وتفعيلها
------------------------------

    cd /home/youruser/TaskFlowAIgggg-main

    python3 -m venv venv
    source venv/bin/activate

------------------------------
3.4 تثبيت الاعتمادات (مكتبة dotenv)
------------------------------

    pip install python-dotenv

(وأي مكتبات أخرى قد تحتاجها حسب المشروع.)

------------------------------
3.5 إعداد ملف .env على الـ VPS
------------------------------

أنشئ ملف .env في نفس المجلد:

    nano .env

ثم ضع المحتوى:

    BOT_TOKEN=توكن_البوت_من_BotFather
    ADMIN_USER_IDS=123456789,987654321

احفظ الملف (في nano: Ctrl+O ثم Enter، ثم Ctrl+X).

------------------------------
3.6 تشغيل البوت على الـ VPS للاختبار
------------------------------

وأنت داخل venv ومن داخل مجلد المشروع:

    python3 comprehensive_bot.py

راقب السجل:
- يجب أن ترى سطرًا مثل:

    ✅ نظام DUX الشامل يعمل: @اسم_البوت

- جرّب إرسال /start من حساب تيليجرام.
- جرّب عمل طلب إيداع أو سحب.
- تأكد أن إشعار الطلب يصل إلى حساب الأدمن (IDs داخل ADMIN_USER_IDS).

------------------------------
3.7 تشغيل البوت في الخلفية باستخدام screen
------------------------------

لجعل البوت يعمل حتى بعد إغلاق جلسة SSH، يمكنك استخدام screen:

1) تثبيت screen (عادة يكون مثبتًا):

    sudo apt install -y screen

2) إنشاء جلسة جديدة:

    cd /home/youruser/TaskFlowAIgggg-main
    source venv/bin/activate
    screen -S duxbot

3) داخل جلسة screen شغّل:

    python3 comprehensive_bot.py

4) لترك البوت يعمل في الخلفية والخروج من screen:
    - اضغط: Ctrl + A ثم D

5) للعودة إلى جلسة screen ومتابعة السجل:

    screen -r duxbot

لإيقاف البوت:
- ادخل إلى screen مرة أخرى:
    screen -r duxbot
- ثم اضغط Ctrl + C داخلها.
- للخروج من screen بعد التوقف:
    اكتب exit أو Ctrl + D.

---------------------------------
4) ملاحظات هامة
---------------------------------

1) لا يجب أن يكون هناك أكثر من نسخة من البوت تعمل بنفس BOT_TOKEN في أي مكان آخر (مثل Replit أو VPS آخر)، وإلا قد تظهر أخطاء من نوع 409 Conflict.

2) تأكد دائمًا من:
    - قيمة BOT_TOKEN صحيحة.
    - ADMIN_USER_IDS تحتوي على Telegram IDs صحيحة للأدمن
      (هؤلاء هم من يستقبلون إشعارات الطلبات).

3) لو لم تصلك إشعارات فورية عند إنشاء طلب من عميل:
    - تأكد أن ADMIN_USER_IDS مضبوط في .env
    - تأكد من إعادة تشغيل البوت بعد تعديل .env
    - تأكد من عدم وجود سكربت آخر يعمل بنفس التوكن في مكان آخر.

4) ملفات CSV (users.csv، transactions.csv، ...):
    - يتم تحديثها مباشرة بواسطة البوت.
    - يجب عدم حذف الأعمدة (Header) إذا تم فتحها يدويًا في Excel.

---------------------------------
5) ملخّص سريع
---------------------------------

- محليًّا:
    - أنشئ venv (اختياري)
    - ثبّت python-dotenv
    - تأكد من load_dotenv() في بداية comprehensive_bot.py
    - أنشئ .env يحتوي على BOT_TOKEN و ADMIN_USER_IDS
    - شغّل: python comprehensive_bot.py

- على VPS:
    - انسخ المشروع للسيرفر
    - ثبّت Python و venv
    - أنشئ venv وفعِّله
    - ثبّت python-dotenv
    - أنشئ .env بنفس القيم
    - شغّل: python3 comprehensive_bot.py
    - استخدم screen أو systemd لجعل البوت يعمل دائمًا في الخلفية.

انتهى.
